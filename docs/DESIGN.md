# InfraView 产品与交互设计

## 目标用户与原则

面向需要集中查看 Linux 基础设施状态的运维人员。界面采用低饱和深色中文控制台，桌面优先并兼顾常见平板宽度。状态同时使用颜色和文字，不能只靠颜色表达。

核心原则：轻量、只读、真实状态、明确降级。页面不出现行级操作菜单，也不展示重启、删除、执行命令、修改或发布入口。

## 页面

### 全局列表与刷新规范

- 所有板块的列表型页面统一使用左对齐数据列，表头和值保持相同对齐方向。
- 数据行除状态列外统一使用相同的紧凑字号、中等字重、正常颜色、行高和等宽字体；主机名不使用额外强调色或加粗。指标异常仅通过警告色或严重色覆盖正常颜色，不额外放大或加粗；状态列保持独立的状态文字、颜色和圆点样式。
- 主机名始终限制在自身固定宽度列内，过长时以省略号截断，不得覆盖或挤占 IP 列；鼠标悬停可通过原生提示查看完整名称。
- 所有刷新区域采用“刷新按钮 + 上次成功刷新时间 + 自动刷新周期”的紧凑组合；请求期间显示“正在刷新…”，成功后恢复显示最近一次浏览器收到数据的时间。
- 上次刷新时间与上游采集时间语义分离；stale 数据仍单独展示实际采集时间和过期提示。

### 登录

固定账号密码登录。页面明确说明只读边界；失败显示简体中文错误。登录成功进入总览，未认证访问业务路由会重定向到登录页。

### 总览

采用可扩展的“板块告警摘要卡”。当前展示 Linux 主机与 MySQL 两个独立板块；Linux 卡片给出整体状态、异常主机数、严重/警告主机数，再按 CPU、内存、IO、网络展示异常数量和等级构成。MySQL 卡片展示可用性、复制线程、复制延迟和复制数据缺失的告警计数。卡片底部不重复展示状态分解，只保留查看入口。整张卡点击进入相应清单，后续其他基础设施板块按相同模式逐个增加。

主机告警口径与主机列表的指标颜色完全一致：离线主机为严重，未知状态主机为警告；CPU、内存、IO 使用配置的百分比阈值，网络取发送与接收中较高等级。同一主机只计入自身最高告警等级，避免严重与警告主机重复计数；各指标异常数按指标独立统计。总览告警摘要复用一次主机当前指标查询，不额外请求数据源，也不是独立的告警事件系统。

卡片保持深色紧凑布局，严重、警告、正常同时使用颜色和明确中文状态。异常计数为零时使用绿色“无严重”“无警告”“无离线”“无未知”和“无异常”文案，不用异常色展示零值。总览刷新区域与列表页一致，展示上次成功刷新时间、后端运行时下发的自动刷新周期和请求中的“正在刷新…”。

### 主机列表

支持主机名或 IP 搜索、在线/离线筛选、名称/CPU 使用率/内存使用率/负载/IO/网络/运行时间排序和分页。每页数量可选择 20、50 或 100 条，默认 20 条；切换数量后回到第 1 页。列表在 IP 后展示可选的 `CPU 核数` 和 `内存容量` 资产配置，分别使用“8 核”“32 GiB”格式；与 CPU、内存使用率明确分列，数据源未提供配置时显示“暂无数据”，不以 0 或推测值代替。IO 按忙碌度排序，网络按发送与接收总吞吐量排序，缺失指标始终置后。搜索、筛选、排序、页码和每页数量均写入 URL，刷新与分享 URL 后可恢复；非法每页数量规范为 20。刷新控制旁显示浏览器最近一次成功收到数据的时间和后端运行时下发的自动刷新周期，请求期间显示“正在刷新…”。列表使用 11 个单行列，主机名不可点击，也没有业务操作列。

### 主机详情

当前版本不提供主机详情页。主机清单直接集中展示主机名、IP、CPU 核数、内存容量、CPU 使用率、内存使用率、负载、IO 忙碌度、网络出入速率、运行时间和状态，主机名不可点击。

### MySQL 实例列表

MySQL 页面从总览卡或导航进入，保持深色紧凑表格与统一刷新控件。清单固定为 10 列：实例地址、版本/角色、连接、线程、QPS/TPS、慢查询、Buffer Pool、复制状态/延迟、运行时间、状态。支持按实例标签精确筛选，自由搜索仅匹配实例地址，并支持状态与角色筛选、固定字段排序和 20、50、100 分页；这些状态写入 URL，刷新后恢复。`sort=instance` 按 IP 与端口自然升降序，QPS/TPS 合并列仍明确按 QPS 排序。

复制线程任一明确停止即为严重；有效复制延迟最大值达到 5 秒为警告、达到 30 秒为严重。复制通道、线程或延迟缺失不伪造零值：可写且未配置复制显示“未配置复制/正常”，其他不完整复制数据为“未知”；未知实例单独计数，并计入卡片警告侧。Linux 与 MySQL 原始样本连续 2 个预期采集周期未推进显示“采集延迟”，连续 5 个周期未推进显示“采集失联”；MySQL 近期身份保留 24 小时，避免停止采集后立即从清单消失。页面不提供 MySQL 历史曲线、实例详情、编辑、执行或写入控件。

## 加载、空态与错误

- 首次请求显示页面级加载状态。
- 指标缺失显示“暂无数据”。
- stale 数据显示“数据已过期”和采集时间。
- Linux 与 MySQL 使用 `tlast_over_time` 返回的原始最后样本 Unix 时间识别是否推进；Service 使用本地最后观察到推进的时刻计算等级，不直接比较原始时间与当前时间。Nightingale Target 在线时间只表达资产状态。默认 15 秒周期下，连续 30 秒未推进为警告、75 秒未推进为严重；进程重启后重新建立基线。
- 没有缓存时显示明确错误；可重试错误提供只读“重试”按钮。
- 后台刷新失败时，主机清单保留已缓存内容并独立提示刷新失败。

## 可访问性与真实浏览器验收

页面使用语义化 heading、table、label、alert 和状态文字；指标异常同时使用颜色与服务端等级属性表达。Playwright 在真实 Chromium 中验证总览、主机清单、筛选、指标列和不存在破坏性按钮或链接。
