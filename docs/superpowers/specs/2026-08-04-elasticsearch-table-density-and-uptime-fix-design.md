# Elasticsearch 表格密度与运行时间修复设计

日期：2026-08-04

## 目标

- 1440×900 桌面视口尽量一次看完 Elasticsearch 16 列，不出现页面横向滚动，也不再因角色列强制表格内部横向滚动。
- 节点角色保持单格单行，只展示前两个角色，存在更多角色时追加 `…`，悬停可查看完整角色列表。
- 集群健康显示与既有模块一致的绿色、黄色、红色、灰色状态徽标。
- 修复 Nightingale 已有 uptime 样本却在 API/UI 中变成 `null` 的问题。

## 已确认根因

- `.elasticsearch-table` 固定 `min-width: 150rem`，角色列固定 `min-width: 18rem`，角色值又完整 `join(' / ')`，因此 1440px 必然横向滚动。
- 集群健康当前仅渲染纯文本，没有状态等级样式。
- `elasticsearch_jvm_uptime_seconds` 当前与历史序列均存在，身份标签有效，数值是有限非负数；上游用小数或科学计数文本编码，严格 `strconv.ParseInt` 拒绝后得到 `null`。

## 批准方案

### 角色与表格

- 新增纯展示函数：零角色返回“未知”；一至两个角色完整显示；超过两个角色显示前两个并追加 ` / …`。
- 角色单元格始终设置完整角色列表 `title`，不增加第二行、标签堆叠或展开控件。
- 表格改为 `width: 100%`、紧凑固定布局；移除 150rem/18rem 强制宽度，按 16 列实际内容分配宽度并缩小 padding/font。
- 节点、集群、地址与角色允许单行裁剪并保留 `title`；数值列、运行时间和状态应在 1440px 代表现场值下完整显示。
- 1440×900 下页面和表格均不横向溢出；更窄视口仍由 `.elasticsearch-table-scroll` 提供内部滚动兜底。

### 集群健康

- 复用 `.status-badge` 结构与配色：green→normal、yellow→warning、red→critical、unknown→unknown。
- 文案保持“绿色、黄色、红色、未知”，不改变筛选值、排序字段或后端健康语义。

### 运行时间

- 仅为 uptime 使用专用解析路径，接受 Prometheus 合法的有限非负小数或科学计数文本。
- 对小数秒向下取整，拒绝 NaN、Inf、负数和超过 `int64` 的值；文档数、队列、容量等计数继续使用严格整数解析。
- API 仍输出可空 `uptime_seconds`，前端继续沿用“x天 x小时 / x天 / x小时”格式。

## 验证与边界

- Provider 测试必须先复现科学计数/小数 uptime 被拒绝，再验证合法转换和非法边界。
- Vitest 必须先锁定角色摘要、完整 title、健康徽标等级和 16 列不变。
- Chromium 1440×900 必须验证页面无横向溢出、表格在桌面不横向溢出、16 格单行、角色带省略号且 title 完整、数值代表单元格不截断。
- 完成离线全量后，仅原位重建现有测试 Nightingale 8080；不创建额外端口、不连接生产、不 commit/push。
