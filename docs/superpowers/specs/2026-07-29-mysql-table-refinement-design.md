# InfraView MySQL 表格细化设计

**日期：** 2026-07-29
**状态：** 用户已批准方案 A
**适用分支：** `feature/mysql-module`

## 目标

在不破坏现有紧凑布局和只读边界的前提下，修复 Host/MySQL 可排序表头与单元格左边缘不一致的问题，并优化 MySQL 表格的信息层级：

1. Host 从 CPU 使用率到状态、MySQL 从连接到状态的表头与所属列内容严格左对齐。
2. MySQL 11 个表头在 1440×900 下保持单行，不通过换行或不可读小字号压缩。
3. 第一列只展示实例地址，实例名称改为可精确筛选的“实例标签”。
4. 前端“可写”统一改为“读写”，内部协议值保持 `writable`。
5. Buffer Pool 同列展示容量和使用率。

## 不在范围内

- 不增加 SQL、任意 PromQL、任意代理、实例详情、历史、写接口或运维操作。
- 不改变复制延迟阈值、实例健康等级、缓存、认证或错误正文。
- 不改变 MySQL 11 列数量，不隐藏列。
- 不增加实例级 Nightingale 请求或 N+1。
- 不连接生产，不创建其他开发端口或 Compose 项目。
- 不修改内部 `writable`、`read_only`、`unknown` 协议值。

## 方案选择

采用方案 A“单行语义压缩”：

- 使用短而明确的单行表头。
- 完整表头含义保留在 `title`。
- 重新分配列宽，而不是缩小到不可读字号。
- 第一列释放的宽度用于 Buffer Pool 和复制列。

不采用完整长表头继续缩小字号，也不采用只有缩写或图标的表头。

## 表头与列对齐

### 根因

普通表头直接渲染文本；可排序表头渲染为 `.host-sort-button`。该按钮当前带有额外左右内边距，使表头文字的左起点晚于单元格内容。

### 修复规则

- Host 和 MySQL 共用同一套对齐规则。
- 排序按钮清除默认外观及额外左右内边距。
- 排序箭头保留在标题右侧，但不改变标题文字的左起点。
- `th` 与 `td` 使用相同的水平 padding。
- Host 只修复对齐，不改变字段、列宽或内容。
- Chromium 中指定列的表头文字与首行内容左边缘误差不超过 1px。

## MySQL 单行表头

表头固定为：

1. 实例地址
2. 所属主机
3. 版本 / 角色
4. 连接
5. 线程
6. QPS
7. 慢查询
8. Buffer Pool
9. 复制 / 延迟
10. 运行时间
11. 状态

规则：

- 桌面表头 `white-space: nowrap`。
- 不允许表头通过换行规避宽度预算。
- 必要时允许省略号，完整标题保留在 `title`。
- 1440×900 下所有表头必须完整可见，页面和表格均无横向滚动。
- 1100px 以下恢复表格容器内部横向滚动，不撑宽页面。

## 实例地址与实例标签

### 第一列

- 第一列从“实例”改为“实例地址”。
- 只展示 `address`，不再组合显示 `name · address`。
- 地址仍保留完整 `title`。

### 标签筛选

筛选区在“实例状态”前增加“实例标签”原生下拉框：

- 默认项为“全部标签”。
- 选项来自完整缓存 snapshot 的实例 `name`。
- 去重后稳定排序。
- 选择标签后按 `name` 精确匹配。
- 同名但地址或所属主机不同的实例一起保留。
- 可与状态、读写属性、搜索、排序和分页组合。
- URL 参数名为 `label`，刷新后恢复。
- 搜索框只匹配实例地址或所属主机；标签由下拉框负责。

### API 契约

`GET /api/v1/mysql/instances` 增加白名单查询参数：

```text
label=<exact instance name>
```

响应 `data` 增加：

```json
{
  "available_labels": ["fixture-label-a", "fixture-label-b"]
}
```

`available_labels` 始终从筛选前的完整缓存 snapshot 生成，不因当前标签、状态、搜索或分页而缩减。该字段只包含现有实例名称，不增加 Nightingale 请求。

筛选顺序：

1. 实例标签
2. 实例状态
3. 读写属性
4. 地址或所属主机搜索
5. 排序
6. 分页

## 读写角色文案

- 内部及 API 中 `writable` 保持不变。
- 列表“版本 / 角色”中的“可写”改为“读写”。
- “读写属性”下拉框中的“可写”同步改为“读写”。
- `read_only` 继续显示“只读”，`unknown` 继续显示“未知”。

## Buffer Pool 容量与使用率

### 数据源

测试 Nightingale 的只读预检已确认存在容量指标：

```text
mysql_global_variables_innodb_buffer_pool_size
```

固定 MySQL 即时查询从 13 条增加为 14 条，但仍在一次 `query-instant-batch` 中完成。

### 领域与 API

实例领域模型和 API 增加可空字段：

```text
buffer_pool_size_bytes
```

归并语义：

- 只接受非负、有限数值。
- 多条序列先忽略非法候选，再选择最新有效样本。
- 最新有效时间戳相同但值冲突时返回缺失。
- 无法匹配实例的序列忽略并保持脱敏。
- 容量和使用率都只是信息指标，不参与健康等级或告警。

### 前端显示

表头使用单行 `Buffer Pool`，单元格显示：

| 容量 | 使用率 | 显示 |
|---|---|---|
| 有 | 有 | `容量 / 使用率` |
| 有 | 无 | `容量 / —` |
| 无 | 有 | `— / 使用率` |
| 无 | 无 | `—` |

容量按适合阅读的二进制单位格式化。完整组合值保留在 `title`。
