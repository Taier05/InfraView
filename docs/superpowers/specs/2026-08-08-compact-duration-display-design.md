# 运行时间与通电时间紧凑显示设计

日期：2026-08-08

## 目标

主机、硬盘、MySQL、Redis、Elasticsearch、RabbitMQ、Java 列表中的运行时间或通电时间，正文最多显示两个最高的非零单位，避免完整的“年、天、小时、分钟”文本被固定列宽截断为省略号。完整时间继续保留在原生 `title` 中。

本次只调整前端展示，不改变 API、原始数值、服务端排序、分页、自动刷新、Nightingale 查询、状态或只读边界。

## 显示规则

- 继续按 1 年等于 365 天换算，单位顺序固定为年、天、小时、分钟。
- 完整文本仍包含全部非零单位；列表正文只取完整文本中最靠前的两个非零单位。
- 不补零单位，不把分钟或小时换算为小数，不增加“约”或省略号。
- 只有一个非零单位时只显示该单位。
- `0..59` 秒仍显示“不足1分钟”；缺失、负数或非有限数仍显示“暂无数据”。
- Java 的规范十进制字符串继续使用 `BigInt` 精确处理，禁止转换为 JavaScript `number`。
- 硬盘继续将合法的有限非负 `power_on_hours` 换算为秒；不伪造上游不存在的精度。

示例：

| 完整文本与 `title` | 列表正文 |
| --- | --- |
| `11分钟` | `11分钟` |
| `19小时 54分钟` | `19小时 54分钟` |
| `181天 19小时 54分钟` | `181天 19小时` |
| `1年 181天 19小时 54分钟` | `1年 181天` |
| `1年 5分钟` | `1年 5分钟` |

## 实现边界

共享时长模块新增 `formatDurationDisplay(value)`，统一返回 `{ text, title }`：`text` 为最多两个非零单位的紧凑正文，`title` 为全部非零单位的完整文本。现有 `formatDurationSeconds(value)` 保留完整文本语义；两个入口复用同一数值校验与单位分解，七个页面只消费共享结果，不能各自复制截断逻辑。

CSS 继续保持固定表格布局、单行显示和既有列宽。本次不通过扩大运行时间列、缩小字体、允许换行或增加横向滚动解决问题。

服务端仍按未格式化的秒数或通电小时数排序，升降序、缺失置后和稳定实体 ID 收口规则不变。

## 测试与验收

- 共享 formatter 覆盖零/缺失、单单位、双单位、三至四单位、跨年、跳过中间零单位及超大 `BigInt`。
- 七个列表页验证正文最多两个单位，原生 `title` 保留全部非零单位。
- 运行时间和通电时间排序仍使用原有 `uptime` 或 `power_on_hours` 参数，并在切换排序后回到第 1 页。
- 运行前端 focused 测试、全量测试、typecheck、production build 和 Playwright `--list`；不启动动态浏览器或额外端口。
- 完成后按既有授权原位部署现有测试 8080；不得连接生产 Nightingale，不得输出私密环境或现场数据。

## 明确不做

- 不改变后端字段、传输类型、采集精度或查询数量。
- 不使用小数年、小数天、缩写单位、自动换行或 CSS 字符级截断。
- 不把正文隐藏的低位单位丢失：完整值必须保留在 `title`。
- 不增加 tooltip 组件、详情弹窗、用户配置项或模块专属格式规则。
