# 每页 500 条选项简化设计

日期：2026-08-08

## 决策

七个列表的每页数量统一显示为 `20 条`、`50 条`、`100 条`、`500 条`。

`500` 是普通分页大小，不再使用“全部（最多500条）”文案，也不赋予特殊的“全部加载”或专属分页交互语义。本设计取代 `2026-08-07-list-all-duration-and-disk-error-summary-design.md` 中仅与“全部”文案和 500 专属隐藏翻页行为有关的要求；其他分页、排序、安全和性能契约保持不变。

## 行为

- 选择 `500 条` 后仍写入 `page_size=500`，并回到第 1 页。
- 结果超过 500 条时继续按每页 500 条正常翻页，不截断、不在前端拼接多页。
- 服务端继续对完整筛选结果排序后再分页；自动刷新只请求当前页。
- `20|50|100|500` 使用同一分页控件和同一交互规则，不增加 500 专属条件分支。
- 非法 URL 和 API 参数的既有规范化、400 错误及内部默认语义保持不变。

## 修改范围与验证

- 共享 `ListPage` 把第四项文案改为 `500 条`。
- 七页的 `pageSizes`、URL、请求、响应和后端实现不变。
- 更新共享控件测试、既有规格/计划和状态文档中的旧“全部”措辞。
- 前端定向测试、全量测试、typecheck、production build 与 Playwright `--list` 通过后，原位部署到测试 8080。

不修改 Go、Nightingale 查询、数据模型、排序字段、自动刷新周期或只读边界。
