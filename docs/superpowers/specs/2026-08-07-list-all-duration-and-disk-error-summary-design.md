# 列表全量查看、运行时长与硬盘错误摘要优化设计

日期：2026-08-07

## 目标与范围

本设计同时解决三个只读展示问题：

1. 主机、硬盘、MySQL、Redis、Elasticsearch、RabbitMQ、Java 七个列表在现有每页 20、50、100 条之外，提供单页最多 500 条的集中查看能力。
2. 主机、MySQL、Redis、Elasticsearch、RabbitMQ、Java 的“运行时间”统一改为“年、天、小时、分钟”动态展示；硬盘“通电时间”复用同一展示规则。
3. 硬盘错误摘要只突出非零项，明确提示还有更多错误，统一无错误文案，并加入 `smart_device_command_timeout` 命令超时次数。

本次不改变 Nightingale 数据的秒级原始值、现有全量排序语义、自动刷新周期、状态等级计算、缓存或 freshness 逻辑。页面和 API 始终只读，不增加任何运维操作、任意 PromQL、代理或 N+1 请求。

## 列表单页最多 500 条

### 交互规则

- 每页数量保留 20、50、100，并新增“全部（最多500条）”。
- “全部”使用 500 作为明确的单页安全上限，不承诺一次渲染超过 500 条记录。
- 当前筛选结果不超过 500 条时，选择该项后全部结果位于第 1 页，不显示无意义的翻页操作。
- 当前筛选结果超过 500 条时，仍按每页 500 条分页，不静默截断；控件文案应明确这是 500 条单页上限。
- 切换每页数量后回到第 1 页，并把选择写入 URL，刷新、前进后退和分享链接后能够恢复。
- 默认值仍为 20，非法、空白或不受支持的 URL 值继续规范化为 20。

### API 与 Service 契约

- 复用现有数字参数 `page_size`，将允许值从 20、50、100 扩展为 20、50、100、500；不引入 `page_size=all`、`page_size=0` 或额外分页模式字段。
- 响应结构保持不变，`page_size` 在该模式下返回 500，`total_pages` 继续按总数和 500 精确计算。
- Service 必须继续按“完整筛选结果 → 服务端排序 → 分页切片”的顺序处理，前端不得对当前页进行本地排序。
- 所有字段的升降序、缺失置后和稳定 ID 收口规则保持不变；增加 500 条选项不能改变排序结果。
- 页码和乘法偏移继续进行溢出保护，未知分页参数继续返回安全的查询错误。

### 性能边界

- 500 是兼顾集中浏览与 15 秒自动刷新的安全上限，避免一次渲染数千行及大量单元格。
- 不引入虚拟滚动、无限滚动或第二套表格组件。
- 每次刷新仍只获取当前列表请求；不得为“全部”额外逐页请求或并行拼接结果。

## 运行时间统一展示

### 格式化规则

前端提供一个共享、纯函数式的时长格式化工具，按以下规则处理非负秒数：

- 1 年固定按 365 天计算，不使用自然年或日期换算。
- 依次计算年、天、小时、分钟，值为 0 的单位不显示。
- 秒数向下取整到完整分钟，不改变后端保存和传输的秒级值。
- 0 至 59 秒统一显示“不足1分钟”。
- 缺失值显示“暂无数据”。
- 单元格继续保持单行，完整文本保留原生 `title`；长时间值允许按共享表格规则省略。

示例：

- `90` 秒：`1分钟`
- `3600` 秒：`1小时`
- `90180` 秒：`1天 1小时 3分钟`
- `508天 6小时`：`1年 143天 6小时`
- `1年 5分钟`：`1年 5分钟`

主机、MySQL、Redis、Elasticsearch、RabbitMQ 继续使用 API 中的数值秒数。Java 的 `uptime_seconds` 继续使用规范十进制字符串和精确整数运算，禁止为了格式化转成可能丢失精度的 JavaScript `number`。

硬盘 `power_on_hours` 不改变后端字段或 Nightingale 指标；前端将非负小时值换算为秒后复用共享格式化工具。若上游只有整数小时，分钟单位自然不会凭空出现；不得伪造精度。

### 排序规则

- 排序仍由 Service 使用未格式化的原始运行秒数或通电小时数完成，不按“年、天、小时、分钟”的中文文本排序。
- 升序、降序均保持缺失值置后，并继续以稳定实体 ID 升序收口。
- 仅修改前端显示不能改变 API 类型、查询字段、排序白名单或原始数据精度。

## 硬盘错误摘要

### 当前字段与目标字段

保留现有七项：

1. 待处理扇区
2. 重映射扇区
3. 不可修复扇区（现有字段 `uncorrectable_sectors`）
4. CRC 错误（现有字段 `udma_crc_errors`）
5. 介质完整性错误
6. 错误日志
7. 异常断电

新增第八项“命令超时”，唯一数据源为固定指标 `smart_device_command_timeout`。该指标表示硬盘未响应命令的累计超时次数；不同厂商的 SMART 原始表达可能存在差异，因此第一期只展示和排序，不设置统一告警阈值。

### 正文与悬浮规则

- 只有已知且大于 0 的项目进入错误正文；值为 0 的项目不显示，缺失值不伪装成 0。
- 正文按固定优先级最多显示两项：待处理扇区、不可修复扇区、重映射扇区、介质完整性错误、CRC 错误、命令超时、错误日志、异常断电。
- 非零项超过两项时，正文在第二项后明确追加 ` · …`，让用户知道悬浮后还有完整内容。
- 原生 `title` 按相同顺序展示全部非零项，不求和、不省略。
- “异常断电”继续显示为“异常断电 N 次”，并在完整提示中注明“累计次数，仅展示，不参与状态判断”。

无非零项时：

- 所有计数均已知且为 0：正文和 `title` 均为“未发现错误”。
- 部分计数已知且为 0、部分缺失：正文为“未发现错误”，`title` 为“未发现错误；部分指标暂无数据”。
- 所有计数均缺失：正文和 `title` 均为“暂无数据”，不能误报为没有错误。

### 命令超时数据契约

- 精确 Nightingale 指标名固定为 `smart_device_command_timeout`，不得接受前端、API 或配置覆盖。
- 复用现有 SMART 辅助指标身份契约：必须包含非空 `ident + device`；可选 `serial_no`、`wwn` 只有在指标序列与库存序列双方都非空时才参与一致性校验。
- 无法匹配库存设备、缺少必需身份、可选身份明确冲突或设备没有当前健康上报的序列均安全忽略，不能创建新硬盘。
- 值只接受有限非负数；负数、非有限值、非法样本、较旧样本忽略，同一最新时间的不同值按现有冲突规则置为缺失。
- 指标缺失表示“暂无数据”，不能猜测为 0；值为 0 才表示已采集且未报告命令超时。
- 在现有固定单次 batch 中增加恰好一条代码内置查询，当前 18 条固定查询变为 19 条；不得增加第二次请求或按设备查询。
- 在 `internal/disk`、Service、HTTP View 和前端类型中增加可空命令超时计数字段，保持空值语义。
- 命令超时进入错误摘要展示和“错误摘要”排序，但第一期不直接改变硬盘状态、总览告警或状态来源。
- 命令超时的标签和真实值不得进入日志、错误消息、测试快照或文档示例。

### 错误摘要排序与状态边界

- “错误摘要”排序继续使用可用于错误判断的已知计数之和；新增命令超时后将其计入。
- 异常断电仍不参与错误摘要排序，因为它是累计历史事件，不代表当前设备错误。
- 全部可排序错误计数缺失时才视为排序缺失；升降序均置后，相同值以设备稳定 ID 升序收口。
- 正数错误计数仍仅用于摘要展示和排序，不直接改变设备状态。
- 硬盘状态继续只由 SMART 健康、Critical Warning、可用备用空间阈值、属性失败和采集等级决定。

## 架构与兼容边界

- 七个列表继续复用现有 `ListPage`、分页控件和共享表格样式，不增加模块专属分页壳。
- 运行时间格式化放入共享前端工具，各页面只负责传入经过运行时校验的原始值。
- API 路径、响应包络、筛选参数和排序字段保持兼容；仅扩展 `page_size=500`，以及在契约满足后为硬盘错误对象增加可空字段。
- Nightingale 查询仍固定、只读、一次 batch、无 N+1；不接受前端、API 或配置传入 PromQL。
- 不读取或输出私密环境文件、Token、Cookie、认证头、Base URL、真实标识、地址、数量、容量、指标值或上游正文。

## 测试与验收

按 TDD 实施，至少覆盖：

- Service：七个列表接受 500、拒绝其他分页值；完整结果先排序后按 500 分页；升降序、缺失置后和稳定 ID 收口不回归；超大页码保持溢出安全。
- HTTP：`page_size=500` 成功且响应结构、总数和总页数正确；非法、空白、0、负数和溢出参数返回安全 400。
- 前端分页：七页显示新增选项，切换后回到第 1 页、URL 和请求使用 500，结果超过 500 时仍正常分页，非法 URL 规范化为 20。
- 时长工具：0、59 秒、1 分钟、整小时、跨天、跨年、隐藏 0 单位、缺失值和超大 Java 整数；六个运行时间页面及硬盘通电时间均使用共享结果。
- 时长排序：证明展示文本变化不影响后端原始数值排序及缺失置后。
- 硬盘摘要：单项、两项、三项以上省略号、完整 `title`、全零、部分缺失、全缺失、异常断电说明及固定优先级。
- 命令超时：固定查询数和顺序、合法归并、零值、缺失、非法值、重复与冲突；API 可空字段、前端运行时校验、摘要展示和排序；状态与总览不受其正数值影响。
- 安全：无写 API、运维控件、任意 PromQL、额外 batch、N+1 或敏感信息输出。

最终验证包括相关 focused 测试、前端全量测试、typecheck、production build、Go gofmt/vet、全仓普通与 race 测试、编译和 Playwright 静态发现。部署、重启、提交和推送继续分别遵守明确授权边界。

## 明确不做

- 不允许单页超过 500 条，不实现虚拟滚动、无限滚动或客户端逐页拼接。
- 不改变 15 秒自动刷新、缓存 TTL、采集时间或 freshness 规则。
- 不按格式化后的运行时间文本排序，不改变后端秒级数据。
- 不把缺失错误计数当作 0，不把全部缺失显示成“未发现错误”。
- 不因错误计数或命令超时直接改变硬盘状态、总览告警或状态来源。
- 不删除错误日志或异常断电，不拆分错误摘要为多列。
- 不增加导出、批量操作、详情写操作、历史趋势或其他运维能力。
