# InfraView 总览四槽位与硬盘展示细化设计

日期：2026-07-30
状态：已批准
范围：总览卡片布局与硬盘列表展示语义；不改变 Nightingale 查询、领域状态、API schema 或只读边界

> 2026-08-01 替代说明：本文“型号 / 容量”同列两行是当时的展示修复，当前已由 `docs/superpowers/specs/2026-08-01-disk-capacity-metric-and-column-design.md` 替代为“型号”“容量”两个独立列，并新增容量服务端排序；总览固定四槽位及其他语义不变。

## 背景与根因

主机硬盘卡加入总览后，`.overview-compact-grid` 被改为桌面三列，导致 Linux、主机硬盘、MySQL 三张卡重新等分并铺满整行，破坏了此前确认的“一行四个固定模块槽位”基线。现有测试只断言网格 class 和无横向溢出，没有锁定桌面四列几何。

硬盘“型号 / 容量”当前使用单行文本并整体省略。测试 Nightingale 与 API 脱敏探针确认容量字段有效；长型号占满单元格后，尾部容量被视觉裁切，问题不在 Provider 或 API。

错误摘要已经接入待处理扇区、重映射扇区、不可校正扇区和 unsafe shutdown 等累计 SMART 计数，但 unsafe shutdown 的中文标签与单位不够直观。

## 最终交互设计

### 总览固定四槽位

- 桌面宽度下固定 `repeat(4, minmax(0, 1fr))`。
- 当前三张卡依次占前三个槽位，第四槽位保持空白；后续模块只向后追加。
- 中等宽度保持两列，窄屏保持一列。
- 不添加占位卡、空白 DOM 或虚假模块。

### 型号与容量

- “型号 / 容量”仍为同一列，但改为紧凑两行。
- 第一行显示型号，可单独省略并保留完整 `title`。
- 第二行显示格式化容量，不受型号长度影响；容量缺失时沿用“暂无数据”。
- 不新增查询，不从型号推测容量，不修改 `capacity_bytes` API。

### 寿命

- 缺失寿命保持当前“暂无数据”，不改成 `-`。
- 已有寿命继续显示“已用 N%”。

### 错误摘要

- `unsafe_shutdowns` 的中文标签统一从“非安全关机”改为“异常断电”。
- 非零值显示为“异常断电 N 次”；完整提示注明这是累计次数、仅展示、不参与状态判断。
- 机械盘的待处理扇区、重映射扇区、不可校正扇区继续保留在错误摘要。
- 零值不逐项展示；多个非零项时正文最多展示两项，`title` 保留全部已知非零项。
- 各项不求和，也不因计数非零直接套用 InfraView 通用阈值。

## 测试与验收

### RED→GREEN

- 前端单元测试锁定型号与容量为两个独立展示元素，长型号不能隐藏容量。
- 单元测试锁定寿命缺失仍为“暂无数据”。
- 单元测试锁定“异常断电 N 次”、完整累计语义提示，以及三个机械盘扇区计数仍参与错误摘要。
- 在现有 8080 上用 Chromium 几何断言先复现桌面三列 RED，再验证四个 CSS 轨道、卡片宽度约为容器四分之一且第四槽位留空。

### 回归

- 前端全量 Vitest、typecheck、production build。
- Go 代码未变时无需新增 Go 行为；最终无缓存镜像仍运行全仓普通/race 测试和编译。
- 只在用户授权范围内原位重建仍连接测试 Nightingale 的现有 8080；不创建其他 InfraView 端口。
- Chromium 验证九列表格无页面或表格横向溢出、容量可见、无破坏性控件、登录后无浏览器错误。

## 安全与非目标

- InfraView 继续严格只读。
- 不新增 SMART 自检、扫描、修复、启停、擦除或远程命令。
- 不新增任意 PromQL、范围查询、上游代理或本机 `smartctl`。
- 不输出或记录私密环境、Token、Cookie、Base URL、真实标识、数量、指标值或上游正文。
- 不连接、切换或探测生产 Nightingale。
- 本轮不处理前端依赖审计项，不提交或推送，除非用户另行授权。
