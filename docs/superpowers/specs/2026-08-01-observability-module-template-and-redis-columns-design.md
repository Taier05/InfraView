# InfraView 观测模块模板与 Redis 列调整设计

日期：2026-08-01

## 目标

1. 调整 Redis 实例页的内存、复制和运行时间展示，消除合并列的语义混淆。
2. 建立可复用的总览卡和列表页模板，后续模块不再复制一套近似但不一致的 JSX/CSS。
3. 保持 InfraView 严格只读、固定 Nightingale 查询、一次 batch 和无 N+1 边界。

## 范围

本轮修改 Redis 页面、对应共享展示组件、测试和文档。主机、硬盘、MySQL 不做行为或布局重构；后续修改这些模块时再逐个迁移到共享模板。新增观测模块必须直接使用共享模板。

不新增、删除或替换 Redis Nightingale 查询，不改变 Redis 状态阈值、API 字段、缓存、freshness、分页或排序白名单。页面不再展示过期/淘汰速率，但后端现有字段和固定查询继续保留。

## Redis 最终列

Redis 实例页固定 11 列，顺序如下：

1. 实例地址
2. 角色
3. 内存上限
4. 内存使用率
5. 连接
6. QPS/命中率
7. key总数
8. 复制链路
9. 延迟
10. 运行时间
11. 状态

删除页面中的“过期/淘汰key数”列。它仍是后端只读展示字段和数据源固定查询的一部分，不影响既有告警与安全契约。

### 内存

- “内存上限”对应 `redis_maxmemory` / `max_memory_bytes`，不是宿主机物理总内存。
- `max_memory_bytes > 0` 时按 IEC 单位显示；为 `null` 时显示“暂无数据”，为 `0` 时显示“未设置上限”。
- “内存使用率”使用既有 `memory_usage_percent`；有效时显示一位小数百分比，缺失时显示“暂无数据”。
- 不新增主机总内存查询或 Redis 与主机资产关联。

### 复制链路与延迟

- 主节点的“复制链路”显示 `—`，因为 `master_link_status` 是从节点到上游主节点的链路语义。
- 从节点的 `master_link_up=true` 显示“正常”，`false` 显示“断开”，缺失显示“未知”。
- 未知角色显示“未知”。
- “延迟”仅展示既有 `worst_replica_lag_seconds` / `redis_replication_lag`；有效时显示秒，缺失显示 `—`。
- `master_last_io_seconds_ago` 只是距最近主库通信时间，不作为复制延迟回退，不在“延迟”列伪装成 lag。
- 链路与延迟的现有状态阈值和 `status_source=replication` 规则不变。

### 运行时间

- 运行时间与主机/MySQL 使用完全相同的天/小时格式。
- 同时有天和小时显示“x天 x小时”；整天显示“x天”；不足一天显示“x小时”。例如 25 小时显示“1天 1小时”。
- 小于 1 小时显示“0小时”；缺失显示“暂无数据”。
- 本轮只调整 Redis，主机和 MySQL 不在本规格中改动。

## 共享观测模块模板

### 列表页模板

建立共享展示组件，统一以下结构与可访问语义：

- `ListPageHeader`：eyebrow、一级标题、说明文本。
- `ListPageControls`：搜索、零到多个筛选器、每页数量和 `RefreshControl`；刷新状态必须位于同一控制栏。
- `ListSearchField`：始终使用带可见标签的 `type="search"`。
- `ListSelectField`：始终使用带可见标签的原生 `select`。
- `ListPageSizeField`：统一 20/50/100 条文案与样式。
- `ListTablePanel`：表格滚动区域、空状态和分页区域。

共享组件负责 DOM 结构、标签关联和公共 class；业务页面只提供文案、选项、值和事件。Redis 可保留自身列宽 class，但不得重新定义输入框、下拉框、刷新区或分页的视觉规则。

stale、初次加载、后台刷新失败和空列表继续使用既有 `StaleBanner`、`ErrorPanel` 与 TanStack Query 状态，不改变数据流。

### 总览模块卡模板

建立 `ModuleStatusCardShell`，统一：

- 模块类别、标题和目标路由。
- normal/warning/critical/empty 等级外观。
- 异常对象总数与严重/警告徽标区域。
- 四格指标告警槽位。
- 空状态和底部“查看模块”入口。

模块仍自行计算状态等级并提供指标文案；共享卡壳只负责一致结构、样式和可访问标签，不承载业务阈值。Redis 先接入该卡壳，Linux、硬盘、MySQL 在后续相关任务中渐进迁移。

## 兼容性与边界

- API 保持原样，前端不新增任意参数或查询能力。
- Redis 仍为固定 21 查询、一次即时 batch、无实例 N+1。
- 页面仍只有只读搜索、筛选、排序、分页和刷新，不增加详情、历史、命令或运维操作。
- 桌面优先完整展示 11 列；容器不足时只允许表格区域横向滚动，文档本身不得横向溢出。
- 共享模板不得引用 Redis、MySQL、硬盘或主机业务类型，避免反向耦合。
