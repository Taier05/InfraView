# InfraView MySQL 紧凑布局设计

**日期：** 2026-07-29
**状态：** 用户已批准方案 A
**适用分支：** `feature/mysql-module`

## 目标

修正 MySQL 模块首轮测试部署暴露的两个布局问题：

1. 基础设施总览不再由 Linux 与 MySQL 两个大卡片各占半行；桌面内容区按紧凑模块网格布局，优先一行容纳四个模块。
2. MySQL 实例列表参考 Linux 主机列表的紧凑密度，在 1440×900 桌面视口中完整展示 11 列，不出现页面级或表格级横向滚动条。

“一屏展示”指横向完整可见；纵向仍按实例行数正常滚动。首期不隐藏、不删除、不折叠任何 MySQL 列。

## 不在范围内

- 不改变 MySQL 领域模型、健康等级、复制阈值或缺失值语义。
- 不改变 Nightingale 固定 13 查询、单次 batch 或缓存策略。
- 不改变两个 MySQL GET API、认证或错误响应。
- 不新增详情、历史、SQL、任意 PromQL、运维按钮或写能力。
- 不连接生产环境；开发部署始终连接测试 Nightingale。
- 不创建额外预览端口；验证后只重建现有 8080 测试服务。

## 总览布局

### 桌面

- 内容区在常用桌面宽度使用四列等宽网格。
- Linux 主机卡与 MySQL 卡尺寸一致，各占一个网格单元。
- 当前只有两个模块时仍各占四分之一行宽，右侧保留后续模块位置，不拉伸成两个半屏大卡。
- 更宽桌面可继续保持至少四列；新增模块沿同一行顺序填充。

### 响应式

- 中等宽度使用两列。
- 手机宽度使用一列。
- loading、empty、error 和 stale 状态占用与正常模块相同的网格单元，避免状态切换造成整页跳动。

### 卡片密度

- 保留模块名称、整体等级、异常总数、分类告警和跳转入口。
- 缩小卡片内边距、间距、计数字号和分类块高度。
- 分类告警仍保持可读，不通过隐藏告警类别换取宽度。

## MySQL 实例列表布局

### 表格宽度

- 移除当前 `.mysql-table` 的 `104rem` 最小宽度。
- 表格采用接近 Linux 主机列表的桌面宽度预算，并始终限制在内容容器内。
- 在 1440×900 视口下同时满足：
  - `document.documentElement.scrollWidth <= clientWidth`
  - 表格滚动容器 `scrollWidth <= clientWidth`
  - 11 个表头全部可见

### 11 列保持不变

1. 实例（名称与地址）
2. 所属主机
3. 版本 / 角色
4. 连接
5. 线程
6. QPS
7. 慢查询
8. Buffer Pool
9. 复制状态 / 延迟
10. 运行时间
11. 状态

### 紧凑规则

- 参考 `.host-table` 的字号、字重、行高和单行布局。
- 缩小 MySQL 单元格左右内边距及专用列宽。
- 数值格式使用紧凑分隔方式，保留原始含义和单位。
- 实例、版本 / 角色、连接和复制列分配较高宽度；QPS、慢查询、运行时间和状态收紧。
- 不允许长文本撑宽表格；必要时使用省略号，完整内容保留在 `title` 中。
- 不允许通过隐藏列、降低到不可读字号或多行堆叠来规避横向宽度。

## 测试与验收

### TDD

- 先增加失败测试，锁定总览使用紧凑网格 class、MySQL 使用无横向溢出的专用表格 class。
- 保留 11 列 DOM 测试和所有既有状态、筛选、排序、分页测试。

### Chromium

在 1440×900 视口验证：

- 总览 Linux 与 MySQL 卡宽度相同。
- 单卡宽度不超过总览内容区约四分之一，并为同一行后续模块保留空间。
- MySQL 页面与表格滚动容器均无横向滚动。
- 11 列表头、关键格式和状态均可见。
- Linux 主机页面布局无回归。

### 完整验证

- 前端聚焦测试、全量 Vitest、typecheck、production build。
- Go 普通测试、race 和生产镜像构建。
- E2E safety、Mock smoke 与 Chromium。
- 验证通过后只重建现有 `infraview` Compose 项目的 8080 测试服务。
- 8080 使用测试 Nightingale；不创建或保留其他预览项目、端口或容器。

## 安全与部署边界

- InfraView 继续只展示数据，不执行任何运维操作。
- 不输出私密环境文件、凭据、认证头、Cookie、测试 Nightingale 响应正文、真实标识、地址、资源数量或指标值。
- 不合并、不推送；部署验收完成后由用户决定是否合并。
